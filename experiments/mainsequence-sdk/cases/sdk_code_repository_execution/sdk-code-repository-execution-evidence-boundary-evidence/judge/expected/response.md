The evidence analysis should center **Stop on material ambiguity**: Identify missing authority or unsafe assumptions and request the smallest necessary clarification.

Local configuration presence and schema validation support only a declaration-level conclusion. They do not prove that the intended identity was selected, that an owned operation completed, or that runtime behavior is correct. The governing boundary is: read repository instructions first, derive remote/branch/worktree context from Git, freeze it before operations, route specialized work, define success evidence, and stop on material ambiguity.

The unsupported column should explicitly reject live success or failure claims that require absent state. The response must preserve ambiguity instead of inventing uids, credentials, logs, releases, runs, or outputs.

The ordered observation column should request the narrowest relevant chain: Git-native identity, applied instruction chain, selected skill route, bounded commands, and the observations in the task's success definition. It should stop when an earlier identity, authorization, or lifecycle prerequisite fails and should preserve unrelated state.
