The evidence analysis should center **Verify Static Site deployment**: Check build state, deployed assets, routing, navigation, and user-visible behavior.

Local configuration presence and schema validation support only a declaration-level conclusion. They do not prove that the intended identity was selected, that an owned operation completed, or that runtime behavior is correct. The governing boundary is: use the installed Command Center SDK, keep delivery static, use opaque platform routing, delegate dynamic work to FastAPI, configure CORS/navigation, and enable branch-driven builds.

The unsupported column should explicitly reject live success or failure claims that require absent state. The response must preserve ambiguity instead of inventing uids, credentials, logs, releases, runs, or outputs.

The ordered observation column should request the narrowest relevant chain: build output and revision, DeploymentRun logs, opaque route resolution, navigation visibility, CORS preflight, and one user-visible API-backed behavior. It should stop when an earlier identity, authorization, or lifecycle prerequisite fails and should preserve unrelated state.
