The evidence analysis should center **Cancel or revoke safely**: Terminate obsolete attempts or credentials explicitly without damaging unrelated provider access.

Local configuration presence and schema validation support only a declaration-level conclusion. They do not prove that the intended identity was selected, that an owned operation completed, or that runtime behavior is correct. The governing boundary is: discover provider/model capability, distinguish built-in from custom ownership, inspect status, use a durable sign-in attempt and next_action loop, and preserve secrecy.

The unsupported column should explicitly reject live success or failure claims that require absent state. The response must preserve ambiguity instead of inventing uids, credentials, logs, releases, runs, or outputs.

The ordered observation column should request the narrowest relevant chain: provider and model identity, credential status, attempt identity and next action, explicit terminal state, and redacted cancellation or revocation result. It should stop when an earlier identity, authorization, or lifecycle prerequisite fails and should preserve unrelated state.
